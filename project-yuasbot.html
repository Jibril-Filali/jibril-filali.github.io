root@projects:~$ cat ./yuasbot/pourquoi.txt

Sur les serveurs Discord FR, le problème c'est que tu dois cumuler 3 ou 4 bots anglophones pour avoir le minimum, et leur modération basée sur des listes de mots interdits se fait contourner en cinq minutes. Le verlan, l'argot, les fautes volontaires, rien n'est pris en compte. Et la moitié des fonctions qui servent vraiment sont derrière un paywall.

yuAs69Bots, c'est ma réponse à ça. Un seul bot, en français, avec une modération IA qui comprend le sens et pas juste les mots. Huit mois de dev pour arriver à quelque chose de stable en prod : 41 cogs (modération, anti-raid, niveaux, tickets, giveaways, confessions, salons vocaux temporaires, etc.), 150+ commandes slash réparties dans 24 groupes, un mute progressif de 5 minutes à une semaine selon les récidives, des codes premium via webhooks Stripe et PayPal, et un dashboard web pour configurer le tout sans toucher aux slash commands.

  • Python côté bot + HTML/CSS/JS côté dashboard
  • 41 cogs chargés dynamiquement au boot (24 GroupCogs + 13 cogs commandes + 4 listener-only)
  • MongoDB (motor, async) pour la persistance

  • Déployé sur Render (Python pinné à 3.11.9 via .python-version)
  • Monitoring crashes en prod via Sentry

Update mai 2026 — la grosse session de l'année. 4 nouveaux cogs (counters, tempvoice, joinall, bot_onboarding), un dashboard web complet, et tout le hardening sécurité qui va avec.

$ 1. Dashboard web (le gros morceau)

Interface aiohttp + Jinja2 + Bootstrap 5 (thème dark) montée en sous-app sur /dashboard. Login via Discord OAuth2 (scopes identify + guilds), sessions chiffrées en cookie via PyNaCl (libsodium). Trois onglets de config par serveur : message welcome (embed riche), modération IA (5 sliders de seuils + multi-select des salons/rôles à ignorer), premium (statut + activation de codes). Pattern POST-Redirect-GET avec flash messages. Le cache du cog AIMod est invalidé à chaque save : pas de reboot nécessaire.

$ 2. OAuth2 mass-add / mass-kick (owner-only)

Flow OAuth2 Discord complet avec scopes identify + applications.commands + guilds.join. Le bot capture le code via redirect_uri, l'échange contre access_token + refresh_token, et stocke le tout en MongoDB. La commande /joinall ajoute en masse tous les users autorisés à un serveur cible (throttle 1 req/sec contre les rate limits Discord), /quitall fait l'inverse.

$ 3. Server counters

Salons vocaux verrouillés en haut du serveur (catégorie "Statistiques") qui affichent automatiquement membres, humains, bots, rôles, channels et boosts. Refresh toutes les 10 minutes via discord.ext.tasks.loop, calé sur le rate limit Discord (2 renames / 10 min / channel). 6 types de counters, setup en une commande.

$ 4. Salons vocaux temporaires

Pattern join-to-create : un salon "Cliquez pour créer" qui, quand un user le rejoint, lui crée un salon vocal personnel avec lui en owner (perms manage_channels + move_members sur ce salon uniquement). Auto-suppression quand le dernier user quitte. L'owner peut renommer, limiter, verrouiller, kick ou transférer l'ownership.

$ 5. Hardening sécurité du dashboard

Middleware aiohttp qui pose tous les security headers : X-Frame-Options: DENY (anti-clickjacking), X-Content-Type-Options: nosniff, HSTS 2 ans, Content-Security-Policy avec allowlist stricte (jsdelivr + cdn.discordapp.com), Referrer-Policy, Permissions-Policy. Cookie de session Secure + SameSite=Lax + httponly. Rate limit sur /redeem à 10 tentatives / heure / user pour bloquer le bruteforce de codes premium.

$ 6. Découverte in-product du dashboard

Quatre entry points pour que les users tombent dessus sans tuto vidéo : slash command /dashboard, champ "Dashboard web" dans les embeds /premium et /botinfo, bouton "Dashboard" sur la page status publique, et un nouveau cog bot_onboarding.py qui DM le owner d'un nouveau serveur dès l'ajout du bot (avec l'URL et un mini-guide de démarrage).

$ 7. Doc client + marketing

PDF client-facing (~20 pages) mis à jour : deux nouvelles sous-sections (counters + tempvoice), section dédiée au dashboard, tableau Free vs Premium étendu, stat passée à 85 commandes. Trois scripts vidéo prêts à filmer (TikTok 45s, demo serveur 1-2 min, YouTube 3-5 min) exportables en PDF via un script Python.

# Bug fix notable : Render utilisait Python 3.14 par défaut (cryptography/Fernet cassé dessus). Pin de Python à 3.11.9 via .python-version (runtime.txt et PYTHON_VERSION ignorés par Render), puis switch d'EncryptedCookieStorage à NaClCookieStorage parce que Fernet restait instable même sur 3.11.

async def _analyse_with_mistral(content: str) -> dict:
    """Envoie le message a Mistral Moderation et renvoie les scores 0-1 par categorie."""
    async with aiohttp.ClientSession() as session:
        async with session.post(
            MISTRAL_URL,
            headers={"Authorization": f"Bearer {MISTRAL_API_KEY}"},
            json={"model": MISTRAL_MODEL, "input": content},
            timeout=5,
        ) as res:
            data = await res.json()
            return data["results"][0]["category_scores"]

# CSP strict : on autorise jsdelivr (Bootstrap) et cdn.discordapp.com
# (avatars + icones de serveur). Pas d'inline JS sauf 'unsafe-inline' style.
_CSP = (
    "default-src 'self'; "
    "script-src 'self' https://cdn.jsdelivr.net 'unsafe-inline'; "
    "style-src 'self' https://cdn.jsdelivr.net 'unsafe-inline'; "
    "img-src 'self' https://cdn.discordapp.com data:; "
    "frame-ancestors 'none'; base-uri 'self'; form-action 'self'"
)

@web.middleware
async def _security_headers_mw(request, handler):
    response = await handler(request)
    response.headers.setdefault("X-Frame-Options", "DENY")
    response.headers.setdefault("X-Content-Type-Options", "nosniff")
    response.headers.setdefault("Strict-Transport-Security", "max-age=63072000; includeSubDomains")
    response.headers.setdefault("Content-Security-Policy", _CSP)
    response.headers.setdefault("Referrer-Policy", "same-origin")
    response.headers.setdefault("Permissions-Policy", "geolocation=(), microphone=(), camera=()")
    return response

tempvoice.py — pattern join-to-create 
# Quand un user rejoint le "creator channel", on lui cree un salon vocal
# perso avec lui en owner, puis on l'y deplace. Auto-cleanup si vide.
@commands.Cog.listener()
async def on_voice_state_update(self, member, before, after):
    if member.bot:
        return
    cfg = await get_config(member.guild.id)
    if cfg is None:
        return

    # 1) Creation : user vient de rejoindre le creator channel
    if after.channel is not None and after.channel.id == cfg["creator_channel_id"]:
        category = member.guild.get_channel(cfg["category_id"])
        ch = await member.guild.create_voice_channel(
            name=f"Salon de {member.display_name}"[:100],
            category=category,
            user_limit=cfg.get("default_user_limit", 0),
            overwrites={
                member: discord.PermissionOverwrite(
                    manage_channels=True,
                    move_members=True,
                    connect=True,
                ),
            },
            reason=f"tempvoice create for {member.id}",
        )
        await register_active(ch.id, member.guild.id, member.id)
        await member.move_to(ch, reason="tempvoice move to own channel")

    # 2) Cleanup : un user quitte un temp -> on supprime si vide
    if before.channel is not None and before.channel.id != cfg["creator_channel_id"]:
        active = await get_active(before.channel.id)
        if active is not None and len(before.channel.members) == 0:
            await before.channel.delete(reason="tempvoice empty cleanup")
            await delete_active(before.channel.id)
